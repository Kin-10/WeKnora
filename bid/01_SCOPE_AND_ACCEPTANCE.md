# 产品范围与验收场景

## 用户主线
创建项目 → 上传招标文件与澄清 → 完整解析并标注来源 → 确认包段与要求 → 确认目录 → 确认本次主体/产品/承诺等事实 → 指定知识库及主要历史标书 → 匹配资料 → 按章节生成与人工编辑 → 插入真实附件 → 检查 → 导出 DOCX。

## 第一版范围
项目和包段管理、招标要求及评分/废标项、目录、本次事实、来源绑定、单章生成、手工编辑保护、基本风险检查、DOCX 输出。支持用户决定主要参考资料；任何来源候选未经确认不得自动成为已审核事实。

## 后续范围
多包段大批量生成、图谱展示、电子签章、自动报价、多人实时协同和自动投标。不得以这些能力阻塞第一版闭环。

## 演示数据
至少准备一份包含两个包段、规定投标格式、技术/商务要求、评分项及资质附件的招标文件；若用历史完成项目回测，排除它的最终标书及复制件，避免答案泄漏。

## 验收故事
- 用户只选包 2：共同要求与包 2 要求进入工作区，包 1 专属资料不能进入输出。
- 某强制证书缺失：检查显示要求原文及定位，项目不能误标记为“已齐备”。
- 历史质保 2 年，本次确认 3 年：正文只采用确认值，若候选资料冲突则提示人工处理。
- 手工修改章节后触发再生成：产生新草稿，不覆盖人工版本；可比较并选择合并。
- 上传澄清更改交付期：生成受影响要求/章节清单并等待确认。
- 导出前审查旧客户名、旧项目名、未确认报价与附件主体/效期。
