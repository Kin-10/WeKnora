# 测试与交付门槛

| 阶段 | 必过验证 |
| --- | --- |
| 0 | 原系统启动或记录无法启动的确切依赖；原有关键能力 smoke test |
| 1 | 项目 CRUD、租户隔离、迁移升级/回滚 |
| 2 | 多包段共同/专属要求、表格/扫描件、来源位置及覆盖报告 |
| 3 | 目录锁定、事实状态、版本冲突 |
| 4 | 权限过滤、错误主体/过期证书、不存在来源 |
| 5 | 单章可追溯、手工编辑保护、重复任务幂等 |
| 6 | 旧项目名、参数矛盾、缺附件、未确认报价、废标项 |
| 7 | DOCX 可打开、目录/编号/表格/原图/附件正确，下载鉴权 |
| 8 | 失败重试、取消、澄清影响范围及旧版保留 |

构建/测试命令从 Phase 0 的实际仓库发现，不预填虚构命令。所有源自模型的关键结论都需来源定位与人工审核状态。抽样评测记录漏检率与误报，并在回测中排除目标项目最终标书。部署文档应列出迁移、存储、队列 worker、文档服务、健康检查、备份与恢复。没有真实客户数据时使用脱敏或合成样本。

最终交付：源代码提交、迁移、配置示例、接口文档、运行手册、测试报告、已知问题清单、一份人工核查过的 DOCX 示例。没有通过实际运行与人工核查的功能标为未验收。
